In the first phase, trajectories were partitioned using a sliding window approach with a 5-minute context window and a 5-minute prediction horizon. 
This specific window size sits at the lower end of context lengths typically used in related inland literature \parencite{donandt2022shortterm, you2020stseq2seq}, and aligns with the collision risk alerting window considered practically
relevant for inland navigation \parencite{donandt2022shortterm}. 
%A 1-minute stride was applied between consecutive samples for all classes except for \texttt{lock}, for which we applied a stride of 10s, due to sparse data availability. %details on lock later
To increase data utility, a 1-minute stride was applied between consecutive samples.

A temporal guard was implemented to discard segments where the elapsed time exceeded the theoretical duration ($T_{ctx} + T_{pred}$), to ensure, that the models only learn from continuous motion sequences without gaps.
This handled both, gaps in the original data and the gaps we introduced with filters in previous preprocessing steps.

\paragraph{Stratified Train-Validation-Test Splitting.}
\label{subsubsec:stratifiedtvtsplit}
Finally, to prevent data leakage, the dataset was partitioned at the vessel level rather than the track level into a 70/15/15 train-validation-test split.
 If the data were split randomly by track ID, the sliding window stride would cause the model to see overlapping temporal segments of the same vessel across the training and test sets. %\\
However, a simple random split at the vessel level is also insufficient due to the high diversity in vessel behaviour and the resulting class imbalance.  To ensure that each data split contains a representative distribution of motion dynamics, we used a stratified split based on $k$-means clustering.
Prior to the split, a three-dimensional feature vector was generated for each unique vessel, made of its mean velocity, maximum absolute \ac{ROT}, and primary geographic context. % note in limitations that OHE was not used but numerical encoding, which implies an order and is wrong in this case
